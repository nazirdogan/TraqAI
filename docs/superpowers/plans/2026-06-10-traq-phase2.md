# Traq Collective Phase 2 — SEO Ranking Surface (dedicated pages) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the single-page site into a multi-page architecture so each priority query cluster (services, fractional Head of AI, UAE, about, FAQ) has its own dedicated, extractable, schema-rich page that can rank top-1–3 and be cited by AI search.

**Architecture:** Add App Router pages under `src/app/**`, driven by a small page-content data layer and a few shared primitives (page hero, breadcrumbs, FAQ block, JSON-LD builders). Each page follows the AEO content patterns: definition-first intro, query-matched H2s, comparison tables, an FAQ block, internal links, and the right schema. Builds on Phase 1’s design system and `JsonLd` helper.

**Tech Stack:** Next.js 14 App Router, TypeScript, Tailwind, schema.org JSON-LD.

**Spec:** `docs/superpowers/specs/2026-06-10-traq-site-reframe-design.md` (§5 IA, §7 SEO/AEO). **Prereq:** Phase 1 merged.

**Verification model:** per task — `npm run typecheck && npm run lint && npm run build`; `curl -sI` each new route → 200; view-source confirms unique `<title>`, canonical, and valid JSON-LD. No unit-test framework.

**AEO content rules (apply to every page):** lead with a 40–60 word standalone answer; H2/H3 phrased as real queries; tables for comparisons; one FAQ block per page wired to FAQPage schema; visible content must match schema; internal links to related service/guide pages; one clear `Book a call` CTA → `/book`.

# Traq Collective Phase 3 — Citation Engine, Lead Magnet & Off-Page — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the content + tools that earn AI citations and inbound — cornerstone guides, comparison pages, an interactive AI Readiness Assessment lead magnet — plus the off-page presence checklist that drives third-party citations.

**Architecture:** A data/MDX-driven `/insights` section (article infrastructure with byline, dates, FAQ, related links, `BlogPosting` schema), comparison pages with tables (`ItemList`/`FAQPage`), and a client-interactive `/ai-readiness` assessment that captures leads through the existing `/api/intake` + Resend pipeline. Off-page work is a delivered checklist doc for Nazir to execute. Builds on Phases 1–2.

**Tech Stack:** Next.js 14 App Router, TypeScript, Tailwind, schema.org JSON-LD; assessment is a client component posting to a new lightweight intake endpoint.

**Spec:** `docs/superpowers/specs/2026-06-10-traq-site-reframe-design.md` (§5 guides/comparison, §6.8 assessment, §7.4 off-page). **Prereq:** Phases 1–2 merged.

**Verification model:** per task — `npm run typecheck && npm run lint && npm run build`; `curl -sI` routes → 200; valid JSON-LD; assessment submit produces an email. No unit-test framework.

**AEO content rules:** definition-first; 40–60 word answer blocks; query-matched H2s; comparison tables; FAQ block per page; visible author byline + “Last updated” date; cite stats with source + date and link; internal links; one `Book a call` CTA.

## Task 4: `/ai-readiness` interactive assessment (lead magnet)

**Files:**
- Create: `src/app/ai-readiness/page.tsx` + `src/app/ai-readiness/AssessmentForm.tsx` (client)
- Create: `src/app/api/intake/assessment/route.ts` (Resend email, mirrors `quick` route: rate-limit, Turnstile, team + lead emails)
- Create: `src/emails/AssessmentLeadEmail.tsx`, `src/emails/AssessmentResultEmail.tsx`

- [ ] **Step 1: Assessment UX**

A short (~8–10 question) scorecard across dimensions (tools in place, team confidence, training done, leadership buy-in, use-case clarity). Client computes a band (e.g. “Early / Building / Ready”) and shows tailored next steps inline. Light, flat, friendly. End with a name/email capture to “send my full results + a tailored plan” → posts to the new API.

- [ ] **Step 2: API route**

`src/app/api/intake/assessment/route.ts` modeled on `quick/route.ts`: Zod-validate `{firstName,email,company,answers,score,band}`, `checkRate('submit-hour', ip)`, `verifyTurnstile`, then Resend a **team email** (`TEAM_INTAKE_EMAIL`, subject `AI Readiness lead: {name} @ {company} — {band}`, include answers + score) and a **result email** to the lead. Reuse env + patterns exactly; do not invent new env vars.

- [ ] **Step 3: Wire CTAs**

Hero kicker + the “AI readiness” guide + a nav/footer link point to `/ai-readiness`. (This is the replacement for the archived ROI calculator.)

- [ ] **Step 4: Verify**

`npm run build`; `curl -sI /ai-readiness` → 200. Submit the assessment locally (dev mode logs the intake without Resend); then after deploy, do a live submission and confirm the team email lands in `nazir@traqcollective.com`.

- [ ] **Step 5: Commit**

`feat: AI Readiness Assessment lead magnet + email pipeline`.
